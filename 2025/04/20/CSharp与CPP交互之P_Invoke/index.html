C# 与 C++ 互操作：P/Invoke 函数、字符串、数组与回调

一言加载中...

person TonyChenn calendar_today 发布于 2025-04-20 edit_calendar 更新于 2026-08-20

1. 适用范围与结论

本文示例面向 Windows 原生 DLL，使用 C ABI、CallingConvention.Cdecl 和显式指针完成 C# 与 C++ 互操作。调用双方必须保持 CPU 架构、调用约定、字符编码、结构体布局和内存释放协议一致；仅仅能够加载 DLL，并不代表复杂参数已经安全跨过 ABI 边界。

对外接口应尽量只暴露固定宽度整数、指针和由调用方明确释放的缓冲区，不要直接把 std::string、std::vector 或带有 C++ 生命周期语义的对象布局暴露给 C#。

2. 前言

术业有专攻，当然编程语言也是这样。而不同的应用场景下单一语言或者并不能满足需求。比如：一些性能要求高的模块可以用CPP实现。常见的如游戏开发引擎，譬如Unity底层使用CPP开发，上层使用C#包装，充分利用两种语言的优势。又比如一些已有的CPP库没有对应语言的库供使用，那么互操作的重要性就体现出来了。

3. C# 与 C++ 互操作的方式

  1. P/Invoke 是可用于从托管代码访问非托管库中的结构、回调和函数的一种技术。它允许托管代码调用非托管代码。对于C#通过P/Invoke可以很方便的实现对CPP方法的调用。但是对于CPP中比较复杂的数据类型时，操作比较繁琐。

  2. C++/CLI 是微软对C++语言做的拓展，允许C++与托管语言的相互操作。非常适合处理非常复杂的数据类型和对象。但语法比较复杂，写起来比较难受，并且只支持windows平台。

  3. 比较新的方案：Mono/CoreCLR。没自己绑定过，后续研究了再补充。

  4. COM互操作，C++/WinRT 也没用过。

DllImport 的一些常用参数如下：

参数 解释
CallingConvention 指定调用约定,调用方需要与被调用方保持一致，如：Cdecl、StdCall
EntryPoint 导入的方法名
CharSet 指定字符集，确保托管字符串与非托管字符串转换时使用约定的编码，如：CharSet.Ansi、CharSet.Unicode
SetLastError 声明被调用函数会设置系统错误码，随后可通过 Marshal.GetLastWin32Error() 获取

这个例子展示了int参数的传递，其他的数据类型对应如下：

C# CPP
int/float/double int/float/double
sbyte char
string char*
IntPtr void*
bool bool

这里的表格只能作为方向说明。bool 的大小和封送规则、long 的平台宽度、结构体对齐方式都可能不同；正式接口应使用 int32_t、uint32_t 等固定宽度类型，并为布尔值显式指定封送方式。

5. string 类型的传递

getName 返回的指针仍由 C++ 对象持有，只能在对象和名称内容保持有效时读取。需要跨线程或长期保存时，应改成“调用方提供缓冲区”或“Native 分配、Native 释放”的明确协议。

6. 数组的传递

这一版直接借用 Cocos2d-x 容器内部的连续指针区，结果只在容器未发生增删和重分配时有效。C# 应立即复制，不能长期保存 headPtr；更稳妥的接口是由 Native 复制一份数组，并提供配套释放函数。
